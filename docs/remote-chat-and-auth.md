# 个人服务器远程聊天与登录设计

本文以 2026-10-08 确认的产品范围为准。一个主账户管理一台公网 Linux 服务和多台本地电脑；不开放多人独立工作区。

## 使用方式

本地 Agent 在单机模式下可不注册、不登录。连接公网 Linux 服务时，浏览器必须登录主账户，再选择云端 Linux Agent 或已经配对、在线的本地 PC Agent。选择的模型和权限必须由目标电脑实际提供和校验。网页承担消息入口和展示，模型调用与工具执行发生在所选电脑。公网 Linux 服务负责认证、消息路由、会话记录、产物存储与恢复。

远程产品交互就是发消息、收回复、选择模型和权限。不增加子任务编排、电脑间转发或远程桌面入口。已有内部持久队列与执行记录用于可靠投递，不作为新的用户操作概念。

## 账户范围

个人服务器只有一个主账户。已有账户通过邮箱和密码登录；首次使用可通过邮箱验证初始化主账户。主账户与已有本地工作区保持同一 ID，初始化不会丢失原模型、项目、会话或电脑记录。

公网首次注册必须受服务器预设的 O_AUTH_OWNER_EMAIL 约束，只有该邮箱收到并验证验证码后才能创建主账户。这避免公网刚启动时被陌生人抢先注册。服务器初始化后关闭初始注册入口，继续提供登录和密码找回。需要额外账户时应另行设计真正的数据和执行隔离。

管理员也可使用已有引导密钥初始化账户，该入口明确标记为“管理员初始设置”。它是部署恢复手段，不要求普通登录提供引导密钥。

## 邮箱验证

服务端随机生成 8 位数字验证码，有效期 10 分钟，单次有效，错误尝试最多 5 次。数据库只保存挑战 ID 绑定的验证码哈希和候选密码哈希；邮箱验证前不改变真实账户。发送者和收件人不来自浏览器任意配置。

流程：

1. 注册页面提交邮箱、名称和新密码；找回密码页面仅提交邮箱。
2. 服务端校验配置、邮箱、输入及频率，登记 delivery_pending 挑战。
3. 服务端调用 Resend，使用挑战 ID 作为发信幂等键，并查询邮件记录核对 ID、发信人、收件人及主题。
4. 已确认的发信记录使挑战进入 awaiting_code。API 表示 verification_requested，页面提醒检查收件箱和垃圾邮件；这不宣称邮件已经到达。
5. 用户提交验证码。注册在一个事务中更新主账户、登记邮箱验证、消费证明、撤销旧会话；找回密码同样在一个事务中替换密码并撤销全部旧会话。
6. 服务端读回账户与挑战的权威状态。注册签发会话后，浏览器再次查询 auth/session，才能打开工作区；重置密码后重新登录。

若服务商调用或读回失败，挑战记录为 delivery_unconfirmed，无法用于注册或改密。若新的邮件失败，旧的、尚未过期的已确认挑战保持可用；只有新邮件被确认后才替换它。断线或响应丢失时不会把不确定的邮件宣称为完成；可以稍后重新申请。验证码申请后服务端重启不会丢失已确认挑战。

未获准的邮箱与不存在的邮箱得到同样的申请文案，不返回注册主账户的邮箱。接口响应不包含验证码、密码哈希或邮件凭据。

## 登录和会话

采用邮箱 + 密码，新增或重置密码至少 15 个 Unicode 字符，UTF-8 编码最多 1024 字节。支持密码管理器、自动填充和粘贴，不要求固定字符组合或周期性修改。现有密码继续可登录，既有 PBKDF2 密码格式保持兼容。

会话在数据库中保存令牌哈希，浏览器使用 HttpOnly、SameSite=Strict 的 Cookie；HTTPS 访问时使用 Secure。生产公网配置需要 HTTPS 和认证，不能配置成匿名访问；本地 loopback 的独立运行模式允许免登录。Cookie 有效期 30 天。退出时删除服务器会话并读回；重置密码与退出全部设备撤销旧会话。

签发会话在事务中校验验证密码时使用的凭据哈希，防止密码已被重置、但旧密码的在途登录请求又创建新会话。访问受保护接口遇到 401 时，网页退出工作区并重新显示登录界面。

本地电脑通过已登录的主账户进行配对，后续出站连接使用独立、可撤销的节点凭证；不把账户密码传给执行节点。节点凭证仅用于限定节点 API，不能读取整个工作区。

## 图形／人机验证

接入 Cloudflare Turnstile。启用后，注册和找回密码申请需要人机验证；正常登录不显示，多次失败后显示。服务端必须校验 token、hostname 和 action；不能仅信任浏览器声称的验证成功。浏览器只取得公开 site key，secret key 只在 Linux 服务端保存。

图形验证失败、过期或不可用时明确显示错误，允许重新验证，不在故障时放行。没有配置 Turnstile 时仍保留服务器频率限制。

登录按网络来源和邮箱两个维度限流：15 分钟窗口内 5 次失败触发 15 分钟等待；计数持久化，重启不清空。启用 Turnstile 后，当前窗口至少 3 次失败触发登录人机验证。验证码申请也按来源和邮箱限流，同邮箱两次申请至少间隔 60 秒。限流返回 Retry-After，不永久锁死账户；改密验证成功后清除对应限流记录。

## 部署配置

在服务器的 /etc/o-agent/cloud.env 中配置以下项目，并重启 backend。文件权限保持 root:oagent、0640；勿把 secret 放进前端构建配置、Git 仓库或聊天消息。

| 配置 | 用途 |
| --- | --- |
| O_AUTH_BOOTSTRAP_TOKEN | 至少 32 字符的管理员引导密钥；现有远程认证开关 |
| O_AUTH_OWNER_EMAIL | 可首次注册的主账户邮箱 |
| O_RESEND_API_KEY | 服务端邮件 API 凭据，需要发送和查询邮件记录的权限 |
| O_AUTH_MAIL_FROM | 已验证发信域名下的邮箱，可用 O &lt;auth@example.com&gt; 格式 |
| O_TURNSTILE_SITE_KEY | 公开的网页组件 key |
| O_TURNSTILE_SECRET_KEY | 仅后端使用的验证 key |
| O_FRONTEND_ORIGIN | 公网 HTTPS 地址；须与 Turnstile 域名匹配 |

Resend key 与发信人必须成对配置；Turnstile 两个 key 必须成对配置。设置值缺失或无效不应显示为已启用。邮箱服务未配置时提供明确状态，并保留管理员引导设置入口；本地单机功能不依赖这些服务。

参考：[Resend 发信接口](https://resend.com/docs/api-reference/emails/send-email)、[Cloudflare 服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。

## 验收与当前交付边界

自动化验证应覆盖本地免登录、远程拒绝匿名请求、注册验证后的实际受保护 API、验证挑战及会话重启恢复、邮件服务失败不改变账户、验证码过期／错误次数／重放、密码重置撤销旧会话、旧密码在途登录不能重新签发会话、事务失败回滚、人机验证 hostname/action 绑定及登录限流。

自动化测试使用模拟邮件与验证服务，不发送真实邮件。上线前还需要用实际域名、Resend 与 Turnstile 凭据验收浏览器和邮件收件；没有这些配置不得宣称公网邮箱注册已经可用。远程聊天的即时消息同步、目标电脑模型发现和权限发现仍需与现有节点执行实现单独验收，不因登录界面完成而自动视为完成。
